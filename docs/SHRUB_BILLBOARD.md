# Shrub Billboard Prototype — Implementation Plan

> **Status: IMPLEMENTED (first pass) — 2026-05-30.**
> Shrubs now render as crossed-quad billboards (route a: procedural alpha,
> up-biased normals). Benchmark: avg FPS 30.9 → 100.0 (+223%), 1% low 15.9 →
> 83.3 (+423%) — at the "vegetation off" ceiling. Deferred items
> (texture atlas, hybrid near-field, dedicated billboard editor) remain as
> described below. Companion to [PERFORMANCE.md](PERFORMANCE.md).

## Motivation

The benchmark attributes ~70% of GPU frame time to vegetation, and within that
**shrubs are essentially the entire cost**: ~73K instances of a single species,
each a 3.5–5.3K-vert procedural mesh (branch cylinders + SDF/surface-nets
foliage). The renderer is ~98% GPU-bound, so this is pure vertex throughput:

```
73K instances × ~4K verts ≈ 110–290M verts/frame
```

The shrub is *one shared, instanced mesh* stamped densely across the ground —
ground filler nobody inspects up close. That makes it the ideal candidate for
**cross-quad billboards** (the industry-standard technique for dense
vegetation):

```
73K instances × ~12 verts ≈ <1M verts/frame   (~400× reduction)
```

This does not *reduce* the shrub vertex problem — it **deletes** it as a
throughput concern. Cost then shifts to fragment/overdraw, which is far cheaper
and separately tunable.

**Scope: shrubs only.** Trees (11 m spacing, varied species, viewed against the
sky) keep their full procedural meshes. Only `kind: "shrub"` species route to the
billboard path.

## Background: what a "shrub" is today

- `"shrub"` is a `kind` tag on a herbarium species (`body_plan.kind`), not a
  separate model format. See [flora.rs](../src/world_core/content/flora.rs).
- Placement makes two grid passes — trees at 11 m, shrubs at 4 m
  ([flora.rs:55-57](../src/world_core/content/flora.rs:55)) — selecting species
  whose `kind` matches the pass.
- There is currently exactly **one** shrub species (literally "Shrub" in
  [herbarium.json](../herbarium.json)), and it is the *heaviest-configured plant*
  in the herbarium: `stem_count: 7`, `crown.density: 0.9`, `dense_mass` foliage.
  That config — multiplied by 73K instances — is the cost.
- Shrub meshes are generated by the same `plant_gen` pipeline as trees
  (`generate_tree` → `build_mesh`), instanced via `InstancedPass`.

## What's already in the codebase (reuse, don't rebuild)

- **Instancing path:** `InstancedPass` already renders per-instance prototype
  meshes (box, octahedron, house) with per-instance transform + tint. A shrub
  billboard is just a new tiny `PrototypeMesh`.
  See [instancing.rs:22](../src/renderer_wgpu/instancing.rs:22),
  [instanced_pass.rs](../src/renderer_wgpu/instanced_pass.rs).
- **Alpha pipeline:** an alpha-blending pipeline variant with back-face culling
  disabled already exists ([pipeline.rs:52-77](../src/renderer_wgpu/pipeline.rs:52))
  — exactly what double-sided foliage cards need.
- **LOD split precedent:** `plant_lod_instances` is already a separate
  always-LOD instance buffer ([instanced_pass.rs:31](../src/renderer_wgpu/instanced_pass.rs:31)),
  so routing shrubs to a distinct path has prior art.

### Gap to fill

The instanced shader (`shaders/instanced.wgsl`) is currently **texture-free,
vertex-colored, opaque** — no samplers, no `discard`. The billboard needs an
alpha-cut silhouette, so the new path needs its own fragment logic (see Design
Decision 2).

## Design

### Geometry: 2 vertical + 1 horizontal quad

Two vertical quads crossed at 90° read as 3D from the ground. **But this is a
flyable world** — viewed straight down from altitude, crossed vertical quads
collapse to a thin "+". So add a **third horizontal-ish quad (a top cap)** so the
shrub still reads as a blob from above.

```
   side view            top-down view
   |  /                  +-----+
   | /  <- 2 vertical    |     |  <- horizontal cap
   |/      quads (90°)   |     |     keeps it readable
  /|                     +-----+     from the air
 / |
```

- ~3 quads → ~12 verts, ~6 triangles (×2 if double-sided, but the alpha pipeline
  already disables back-face culling so a single-sided quad shows from both
  sides).
- Unit-sized prototype, scaled per-instance by the existing instance transform
  (height from `PlantInstance.height`, rotation from `PlantInstance.rotation`).
- Quads are **fixed/intersecting**, not camera-facing — no per-frame billboard
  rotation needed; the intersection gives volume from any angle and avoids
  top-down popping.

### Decision 2 (the main one): how to get the silhouette

**Route (a) — Procedural alpha in the fragment shader. RECOMMENDED.**
Compute a bush-blob mask from the quad UV (radial falloff + a little noise),
`discard` below a threshold. Optionally render a flat leaf color with a darker
rim ("outline color") for a stylized, slightly-toon look.
- Pros: no textures, matches the renderer's vertex-colored aesthetic, zero asset
  pipeline, least new infrastructure.
- Cons: limited silhouette detail (fine for ground cover).

**Route (b) — Alpha-tested texture atlas.**
A real foliage sprite with an alpha channel.
- Pros: more realistic.
- Cons: net-new infrastructure (texture loading, samplers, UVs, bind groups in
  the instanced pass, which currently has none); stylistic departure from a
  vertex-colored world.

→ **Start with route (a).** Revisit (b) only if the stylized look proves
insufficient.

### Decision 3: normals (makes or breaks the look)

Flat cards lit by their geometric (sideways) normals look flat. Give the verts
**spherical / up-biased normals** — as if the shrub were a hemisphere — so the
existing day/night lighting makes them catch light like a rounded bush. Cheap,
and it's the difference between "shrub" and "cardboard."

### Decision 4: alpha test vs alpha blend

Prefer **alpha-test (`discard`)** over blending:
- No back-to-front sorting required (impossible with 73K instances anyway).
- Writes depth correctly → no draw-order artifacts.
- If MSAA is enabled, use **alpha-to-coverage** for softer edges nearly free.

### Color

Tint from the species leaf color (already available per species). Reuse the
per-instance tint channel the instancing path already carries.

## Routing shrubs to the billboard path

In `InstancedPass`, branch on species `kind`:

- `kind == "shrub"` → build instances against the `shrub_billboard` prototype
  (alpha pipeline, procedural-silhouette shader).
- `kind == "tree"` (and houses) → unchanged, existing opaque procedural meshes.

Keep the prototype keyed in `ModelRegistry` like the others (e.g. key
`"shrub_billboard"`), uploaded once at startup. Per-chunk instance buffers are
built exactly as today.

## Editor implications (two-pass approach)

The herbarium plant editor edits a `SpeciesConfig` and previews it through the
procedural generator — `generate_plant_mesh` via `merge_params`
([plant_editor.rs:71-77](../src/app/plant_editor.rs:71),
[plant_editor.rs:200](../src/app/plant_editor.rs:200)). Its controls are all
procedural-mesh params: `body_plan`, `trunk`, `branching`, `crown`, `foliage`.

**Once a shrub renders as a hardcoded billboard, none of those controls affect
what's drawn in the world.** Presenting them for a shrub-kind species is
misleading — the user would tweak stems/branching/crown and see no change in the
world (only in the now-irrelevant procedural preview). So the editor needs to
diverge by `kind`.

### First pass — hardcode the billboard, lock it out of the editor

- **Hardcode the billboard model** (geometry, silhouette, normals). Do *not* try
  to derive it from the procedural `SpeciesConfig` fields.
- **Keep the shrub's herbarium entry** — placement still needs it: `biomes`,
  spacing, `weight`, `height_range`, and the leaf **color** (the one param the
  billboard can still honor as a tint). Removing the entry entirely would break
  `place_grid`'s shrub pass.
- **In the editor, hide or lock the procedural-mesh controls for `kind == "shrub"`**
  so the user isn't offered no-op knobs. Options, simplest first:
  - Exclude shrub-kind species from the editor's editable list, or
  - Show a read-only "rendered as billboard — not editable here" notice, leaving
    only color/placement editable.

### Second pass — a dedicated billboard editor

Build a separate editor UI for shrub-kind species exposing the params that
*actually* drive the billboard: silhouette shape/tightness, plane count/layout,
size, leaf color + rim/outline color, and per-instance density/jitter. This is
deliberately deferred — the first pass ships a good-looking hardcoded shrub and
the throughput win without blocking on new editor UI.

> Decision: **hardcode now, editor later.** The rendering win is the priority;
> editability for the billboard shrub is a follow-up.

## Risks & mitigations

- **Overdraw becomes the new cost center.** 73K alpha-tested cards at 4 m spacing
  → many overlapping transparent-edge fragments; `discard` still runs the shader
  on them. Still vastly cheaper than the current geometry. Mitigate with tight
  silhouettes (less wasted quad area), distance fade, and only *then* consider
  lowering the 4 m spacing for denser ground.
- **Top-down flatness.** Addressed by the horizontal top-cap quad (Decision 1).
- **Up-close flatness.** If it ever reads poorly near the camera, add a
  **hybrid near-field**: keep the full procedural mesh within ~20–30 m and
  billboard beyond (reuse the `plant_lod_instances` split pattern). **Defer this**
  — start all-billboard for shrubs; at 4 m density the flatness rarely reads.

## Implementation steps (suggested order)

1. **Add the `shrub_billboard` prototype mesh** — generate 2 vertical + 1
   horizontal unit quad with spherical/up-biased normals and UVs; register in
   `ModelRegistry`.
2. **Add the billboard shader** — variant of `instanced.wgsl` (or a new shader)
   with a procedural alpha mask + `discard`, leaf-color tint, optional rim.
3. **Add the alpha-test pipeline** for the billboard path (reuse the existing
   no-cull alpha pipeline as the starting point; switch blend→alpha-test or
   alpha-to-coverage).
4. **Route by `kind`** in `InstancedPass` so shrubs use the new
   prototype/pipeline and trees/houses stay unchanged.
5. **Lock shrubs out of the procedural editor** (first-pass editor handling):
   hide or disable the procedural-mesh controls for `kind == "shrub"`, keeping
   the herbarium entry for placement + color. See *Editor implications*.
6. **Instrument & measure:**
   - Print per-species mesh vert counts (full vs billboard) to confirm the cut.
   - Run `bun tools/bench.ts` and compare against `benchmarks/baseline.json`.
   - `take_screenshot` before/after for a visual diff (ground level *and*
     aerial).
7. **Tune** — silhouette tightness, normal bias, rim color, and (only after the
   win lands) shrub spacing for denser ground.

## Success criteria

- Shrub vertex throughput drops by ~1–2 orders of magnitude (target: shrub mesh
  ≤ ~12 verts vs 3.5–5.3K).
- Benchmark FPS improves substantially over baseline (~30) — toward the
  "vegetation off" ceiling (~100) — without a uniform spacing increase.
- Shrubs read as rounded, lit bushes from both ground level and the air; no thin
  "+" artifact when viewed top-down.

## Explicitly out of scope

- Tree billboards/impostors (trees keep full meshes).
- Texture/atlas pipeline (route b) — deferred.
- Hybrid near-field full-mesh shrubs — deferred unless up-close flatness shows.
- Dedicated billboard editor for shrub-kind species — deferred to the second
  pass; the first pass hardcodes the model and locks shrubs out of the procedural
  editor (see *Editor implications*).
- Terrain/water LOD — measured negligible; see [PERFORMANCE.md](PERFORMANCE.md).
